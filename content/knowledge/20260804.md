## 한 줄로 말하면

OpenAI의 세 번째 세대 음성 시스템 **GPT‑Live**는 '턴 감지기(turn detector, 누가 말할 차례인지 판단하는 소형 모델)'를 음성 처리 경로에서 완전히 제거하고, 듣기와 말하기를 동시에 처리하는 **풀듀플렉스(full-duplex)** 방식을 도입해 인간처럼 자연스러운 대화 흐름을 만들어냈다.

---

## 왜 중요해요

사람들은 대화할 때 0.몇 초 만에 순식간에 말을 주고받습니다. 그런데 기존 음성 AI는 이 리듬을 따라가지 못했어요. 이유는 구조 자체에 있었습니다.

기존 방식은 크게 두 가지 문제를 안고 있었습니다.

1. **너무 이르게 판단하면** → 사용자의 말이 끊긴다.
2. **너무 늦게 판단하면** → AI의 응답이 느리고 답답하게 느껴진다.

그리고 이 판단이 끝나야만, 훨씬 더 크고 똑똑한 언어 모델(LLM, Large Language Model)이 비로소 일을 시작할 수 있었습니다.

GPT‑Live가 이 구조를 바꿨기 때문에 중요합니다. 이제 음성 AI가 실제 대화처럼 **끊김 없이 흐르는** 수준에 도달했고, 이는 ChatGPT Voice 같은 실제 제품에 바로 적용됩니다.

## 자세히

### 기존 시스템의 한계: 턴 기반 구조

과거 음성 AI 시스템들은 텍스트 기반 LLM의 '순서 교환(turn-based)' 방식을 그대로 물려받았습니다. 사람이 말을 멈추면 → 모델이 처리하고 → 응답을 내보내는 구조였죠. 심지어 초기 '캐스케이드(cascaded)' 방식은 **음성→텍스트 변환 → LLM → 텍스트→음성 변환**을 직렬로 순서대로 실행해서 지연이 더 쌓였습니다.

이후 등장한 '스피치 투 스피치(speech-to-speech)' 모델은 오디오를 바로 처리해서 개선됐지만, 여전히 **턴 감지기에 의존**했습니다. 감지기가 결정을 내리기 전까지는 아무것도 시작할 수 없었기 때문입니다.

---

### GPT‑Live의 핵심 변화: 풀듀플렉스 + 비동기 위임

GPT‑Live는 세 가지 큰 변화를 가져왔습니다.

**① 턴 감지기 제거 & 풀듀플렉스 전환**
음성 모델이 듣기와 말하기를 동시에 할 수 있게 되어, 별도의 감지기가 필요 없어졌습니다. 대화의 흐름 자체를 모델이 직접 제어합니다.

**② 비동기 위임(Asynchronous Delegation)**
깊은 추론이나 도구 사용이 필요할 때는 **GPT‑5.5** 같은 프론티어 모델에 작업을 맡깁니다. 이 과정은 대화 흐름과 **별도의 비동기 경로**로 처리되기 때문에 음성 흐름을 멈추지 않습니다. "말하는 것"과 "깊이 생각하는 것"을 분리한 셈입니다.

**③ 미디어 경로와 애플리케이션 로직의 분리**
오디오는 전용 **빠른 경로(fast path)**를 통해서만 흐릅니다. 도구 호출이나 백엔드 서비스가 느려지더라도 오디오 흐름 자체는 절대 멈추지 않습니다.

---

### 기술 구현: 어떻게 "라이브"를 실현했나

**Go 언어로의 전환**
미디어 프론트엔드와 추론 로직을 기존 Python asyncio에서 **Go**로 다시 작성했습니다. 그 결과 오디오 프레임 전달의 안정성이 크게 향상되어, 새 시스템의 **p95(상위 5% 느린 케이스)** 수치가 이전 시스템의 **p50(중간값)**과 같아졌습니다.

**WebRTC 기반 전송**
**WebRTC(Web Real-Time Communication, 웹 실시간 통신 프로토콜)**를 전송 기반으로 사용합니다. WebRTC는 패킷 손실, 시간 오차, 연결 변경 등의 상황에서도 계속 작동하도록 설계되어 있습니다. 패킷이 늦게 도착하면 음성을 미세하게 늘려 끊김을 막고, 이후 살짝 빠르게 재생해 실시간에 맞춰 따라잡습니다.

**스테이트풀 추론(Stateful Inference)과 끊김 없는 전환**
음성 대화는 오래 지속될 수 있고 그만큼 **컨텍스트(context, 이전 대화 맥락)**가 계속 쌓입니다. 모델 인스턴스(실행 중인 모델 단위)를 교체해야 할 때, 시스템은 다음과 같이 처리합니다.
1. 새 모델 인스턴스를 기존 것과 나란히 준비(웜업)
2. 현재 세션의 컨텍스트를 새 인스턴스에 미리 채워 넣기(프리필)
3. 양쪽에서 동시에 추론을 실행
4. 새 인스턴스가 준비되면 전환

이 방식은 **컨텍스트 압축(context compaction)**에도 적용됩니다. 대화가 길어지면 누적된 컨텍스트가 모델의 한계를 초과할 수 있는데, 기존 모델 인스턴스가 계속 대화를 이어가는 동안 백그라운드에서 컨텍스트를 압축하고 새 인스턴스를 준비합니다. 전환이 끝날 때까지 사용자는 아무것도 느끼지 못합니다.

### 실제 적용

이 아키텍처는 현재 **ChatGPT Voice**를 구동하고 있으며, 새롭게 출시된 컴퓨터 제어 기능 및 ChatGPT 데스크탑 앱에서의 에이전트 조율 기능의 기반이 되고 있습니다.
