## 한 줄로 말하면

LLM(대형 언어 모델, Large Language Model)에게 기존 태그 목록을 보여주는 대신, 태그를 자유롭게 '상상(환각)'하게 만든 뒤 **벡터 임베딩(vector embedding, 텍스트를 숫자 벡터로 변환하는 기술)**으로 가장 가까운 실제 태그를 찾아내는 방식이다.

## 왜 중요해요

Simon Willison은 자신의 블로그에 **1,856개**의 태그가 있다고 밝혔다. 이 많은 태그를 한꺼번에 LLM에 넘겨주고 "이 글에 어울리는 태그를 골라줘"라고 하기엔 너무 많다. 토큰(token, LLM이 처리하는 텍스트 단위) 한계에 걸리거나, 모델이 제대로 고르지 못할 수 있기 때문이다.

이 문제는 비단 블로그 태깅에만 해당하지 않는다. 상품 분류, 문서 카테고리 지정 등 **거대한 기존 어휘(vocabulary) 중에서 맞는 항목을 골라야 하는 모든 상황**에서 같은 벽에 부딪힌다.

## 자세히

Doug Turnbull이 제안한 해법은 발상의 전환에서 출발한다.

**기존 방식 (문제 있음)**
> "다음 1,856개 태그 중에서 이 글에 맞는 것을 골라줘"
→ 태그가 너무 많아 LLM에 한 번에 전달하기 어렵다.

**새로운 방식 (핵심 아이디어)**
1. **LLM에게 기존 태그를 전혀 알려주지 않는다.**
2. 대신 태그가 *어떻게 생겼는지* 예시(형태)만 보여주고, 콘텐츠에 어울릴 것 같은 태그를 **자유롭게 만들어내도록(=환각하도록)** 유도한다.
3. LLM이 상상해서 만든 태그를 벡터 임베딩으로 수치화한다.
4. 기존 태그 코퍼스(corpus, 기존 태그 전체 모음)도 미리 벡터 임베딩해 둔다.
5. 두 벡터 사이의 **거리(유사도)**를 계산해, 가장 가까운 실제 태그를 최종 결과로 사용한다.

원문에서 소개된 프롬프트 예시를 보면 이 전략이 잘 드러난다. 가구·홈리빙 쇼핑몰의 상품 분류를 예로 들어, LLM에게 이런 식으로 지시한다.

> "지금까지 본 적 없는 새로운 가구/홈리빙/철물 분류 체계를 만들어라. 분류는 이런 형태를 참고해라: `Furniture / Living Room Furniture / Coffee Tables & End Tables / Coffee Tables` … 분류할 쿼리: **brown coffee table**"

LLM은 실제 존재하는 카테고리를 몰라도 된다. 그냥 형태를 흉내 내 그럴듯한 분류를 만들면, 나머지는 벡터 유사도 검색이 실제 카테고리로 연결해 준다.

**왜 이게 잘 작동할까?**
- LLM은 수천 개의 선택지를 기억할 필요 없이, 그냥 "잘 어울릴 것 같은 표현"을 생성하는 데만 집중하면 된다.
- 벡터 임베딩은 의미적으로 유사한 텍스트를 가깝게 표현하므로, LLM이 만든 가상의 태그와 실제 태그 사이의 의미적 거리를 효과적으로 좁혀준다.
- 결과적으로 **LLM의 언어 생성 능력**과 **벡터 검색의 정밀함**을 각각의 장점대로 조합한 셈이다.
