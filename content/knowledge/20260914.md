## 한 줄로 말하면

수백~수천억 개의 파라미터를 가진 거대 AI 모델을, GPU 서버 없이 내 컴퓨터의 SSD와 RAM을 영리하게 활용해 실행할 수 있게 해주는 아주 작고 빠른 추론 엔진(inference engine, AI 모델을 실제로 실행·응답 생성하는 소프트웨어)입니다.

## 왜 중요해요

보통 744B(7,440억 개) 파라미터짜리 AI 모델을 돌리려면 수억 원짜리 데이터센터 GPU가 필요합니다. Colibrì는 이 상식을 깨고, **일반 소비자용 하드웨어**에서 같은 모델을 실행할 수 있게 해줍니다.

핵심은 두 가지입니다.

1. **접근성**: 비싼 클라우드 API에 요금을 내는 대신, 모델을 직접 소유하고 내부를 들여다보고 개선할 수 있습니다.
2. **투명성**: 속도가 부족할 수는 있어도, 모델의 정확도나 동작 방식을 몰래 바꾸지 않는다는 원칙을 지킵니다. 빠른 메모리가 부족하면 속도가 느려질 뿐, 모델 자체를 조용히 바꾸는 일은 없습니다.

현재 GLM-5.2/5.3 (744B), Kimi K3 (2.8T), DeepSeek V4.1 Flash (552B), Qwen3 계열 등 아홉 가지 모델 패밀리를 지원합니다.

## 자세히

### MoE 모델의 특성을 이용한 영리한 트릭

Colibrì가 다루는 모델들은 대부분 **MoE(Mixture-of-Experts, 전문가 혼합)** 구조입니다. MoE란 모델 안에 수만 개의 '전문가' 네트워크를 두고, 토큰(글자·단어 단위)마다 그 중 일부만 골라 사용하는 방식입니다.

예를 들어 744B 파라미터 모델이라도, 토큰 하나를 처리할 때 실제로 활성화되는 파라미터는 약 40B에 불과하고, 그중 토큰마다 바뀌는 부분(라우팅되는 전문가들)은 약 11GB 수준입니다. 즉, **전체 모델이 빠른 메모리에 들어갈 필요가 없습니다**.

### AI 메모리 멀티티어링 (AI memory multitiering)

Colibrì는 VRAM(GPU 메모리)·RAM·NVMe SSD(저장장치)를 **하나의 연속된 메모리 계층**으로 취급합니다.

- **자주 쓰이는 부분**(어텐션, 공유 전문가, 임베딩 등 약 17B 파라미터)은 RAM에 상주
- **19,456개의 라우팅 전문가**들은 디스크(약 370GB)에 저장해 두고, 필요할 때만 스트리밍해서 불러옴
- **LRU 캐시**(LRU cache, 가장 최근에 쓴 것을 우선 보관하는 방식)와 **학습된 핫 스토어**(자주 호출되는 전문가를 미리 고속 메모리에 고정)로 속도를 최적화

### 가중치를 위한 JIT (Just-In-Time 컴파일)

원문은 이 방식을 **"가중치를 위한 JIT"** 에 비유합니다. 프로그래밍 언어의 JIT 컴파일러가 자주 실행되는 코드만 골라 컴파일하듯, Colibrì는 자주 호출되는 전문가만 빠른 메모리 계층에 올려둡니다. 라우터(router, 어떤 전문가를 쓸지 결정하는 부분)가 한 레이어 앞서 실행되어 미리 다음에 쓸 전문가를 불러오므로, 디스크 읽기 지연을 숨길 수 있습니다.

### 핵심 기술 요약

| 기술 | 설명 |
|---|---|
| 멀티티어 메모리 | VRAM/RAM/NVMe를 단일 계층으로 통합 |
| 전문가 JIT 배치 | 라우팅 빈도 기반 LRU·핫스토어·프리페치 |
| I/O 최적화 | 배치 전문가 병합, O_DIRECT, 듀얼 SSD 스트라이핑 |
| 이기종 실행 | CPU·CUDA·Metal·NUMA 메모리를 한 런타임에서 혼합 사용 |
| 압축 상태 관리 | 57× 더 작은 MLA KV 상태, 정밀도 손실 없이 메모리 절약 |
| 추측 디코딩 | MTP·문법 기반 드래프트, 효과 없으면 비활성화 가능 |

### 로컬 클러스터 모드

여러 대의 Mac을 묶어 쓸 수도 있습니다. 코디네이터(coordinator)가 토큰 생성·라우팅·KV 상태를 로컬에 두고, 전문가 연산만 다른 머신에 분산합니다. 하나의 레이어 배치 요청을 단일 TCP 연결로 보내기 때문에, 전문가마다 왕복 통신이 발생하지 않습니다.

### 엔진의 크기

전체 엔진은 **단일 C 파일(`c/colibri.c`)과 소수의 헤더**로 구성됩니다. BLAS(선형대수 라이브러리), Python 런타임, GPU 모두 필수가 아닙니다. 코드베이스가 작기 때문에, 누구나 다음 최적화를 기여할 수 있다는 것이 프로젝트의 철학입니다.

### 연구 플랫폼으로서의 역할

Colibrì는 단순 실행 도구를 넘어 **오픈 리서치 플랫폼**을 지향합니다. 모든 최적화는 '가설'로 취급하고, 실제 end-to-end A/B 실험으로만 채택 여부를 결정합니다. 부정적인 실험 결과도 긍정적인 결과만큼 가치 있다고 명시하며, 기여자들에게 하드웨어·커밋·명령어·측정값·로그를 모두 기록해 공유할 것을 요청합니다.
