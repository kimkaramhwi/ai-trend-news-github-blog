## 한 줄로 말하면

DeepSeek가 자사 실제 서비스에 쓰이는 추론 엔진(inference engine, AI 모델이 답변을 생성하는 처리 시스템) 'DeepInfer'를 오픈소스로 공개하고, 클러스터(cluster, 함께 묶인 GPU 서버 집합) 1개로 하루 155조 토큰을 처리하며 80% 이상의 마진을 낸다는 운영 수치를 공개했습니다.

---

## 왜 중요해요

지금까지 고성능 LLM 추론 서비스 스택은 Fireworks, Baseten, Modal 같은 비공개 기업들이 독점해 왔습니다. DeepInfer의 공개는 그 판도를 바꾸는 사건입니다.

- **오픈소스 공개**: Apache 2.0 라이선스로 누구나 사용·수정할 수 있습니다.
- **놀라운 운영 수치 공개**: 하루 155조 토큰 처리, 96% 입력 캐시 적중률(cache hit rate, 이전에 처리한 내용을 재활용하는 비율), 평균 첫 토큰 응답 시간 400ms, 초당 230토큰 생성(코딩 작업 시 300토큰/s)이라는 수치를 발표했습니다.
- **경제성 충격**: GPU 카드 한 장당 시간당 $38 매출, 카드 운영비는 시간당 $5~8 수준으로, 80% 이상의 추론 마진을 주장합니다. 이 마진 기준으로 클러스터 투자 회수 기간은 81일로 계산됩니다.
- **프롬프트 캐싱**: 최대 72시간 프롬프트 캐싱(prompt caching, 같은 입력을 다시 계산하지 않고 저장해 재활용하는 기술)을 지원한다고 밝혔습니다. OpenAI가 최근 발표한 12시간보다 훨씬 깁니다.

단, 이 수치들은 DeepSeek 자체 발표이며 독립적인 검증을 거친 수치가 아닙니다.

## 자세히

### DeepInfer는 어떻게 만들어졌나요?

DeepInfer는 vLLM(오픈소스 LLM 추론 라이브러리)을 기반으로 만들어졌으며, SGLang과 TensorRT-LLM(TRRTLLM, NVIDIA의 추론 최적화 라이브러리)의 기여도 포함하고 있습니다. 여기에 DeepSeek가 자체적으로 많은 기능을 추가했습니다.

지원하는 주요 기능은 다음과 같습니다:
- **분산 추론(distributed inference)**: 여러 GPU에 작업을 나눠 처리
- **투기적 디코딩(speculative decoding)**: 빠른 초안 생성 후 검증하는 방식으로 속도 향상
- **SWA Bounded Replay**: 슬라이딩 윈도우 어텐션 관련 최적화 기법
- **구조화 출력(structured output)**: JSON 등 특정 형식으로 결과 출력
- NVIDIA GPU와 **화웨이 어센드(Huawei Ascend)** 플랫폼 모두 지원

함께 공개된 **deepseek-recipe** 컴포넌트는 실제 서비스 API와 호환되는 토큰 인코딩·디코딩 처리를 담당합니다.

### 아키텍처: 단계별 분리

DeepInfer는 **비전 인코딩(vision encoding) → 프리필(prefill, 입력 처리 단계) → 디코드(decode, 출력 생성 단계)** 세 단계를 분리해 각각 독립적으로 스케줄링(scheduling, 작업 순서 배분)합니다. 토큰 단위가 아닌 계산 단위로 스케줄하는 구조입니다.

### '완전 오픈소스'에도 빠진 부분이 있어요

DeepSeek는 DeepInfer를 "완전 오픈소스"라고 밝혔지만, 실제 서비스를 그대로 재현하기는 어렵습니다. 내부 인프라와 강하게 결합되어 있는 이유로 **KV 캐시(KV cache, 키-값 캐시: 이전 계산 결과를 저장해 재사용하는 메모리 구조) 관리**와 **로드 밸런싱(load balancing, 부하 분산)** 컴포넌트는 아직 완전히 공개되지 않았습니다.

### vLLM 팀의 반응

vLLM 팀은 DeepInfer가 자신들의 코드를 기반으로 만들어졌음을 인정하면서도, GB200 GPU에서 동일한 설정으로 테스트했을 때 **디코드 처리량이 DeepInfer 발표 수치의 6% 이내** 수준임을 확인했다고 밝혔습니다. 재현 레시피와 벤치마크 결과도 함께 공개했습니다. 이는 DeepSeek만의 효율이 기존 오픈소스 엔진으로도 상당 부분 달성 가능하다는 점을 보여줍니다.

### 두 가지 논쟁

이번 공개로 커뮤니티에서는 두 가지 논쟁이 벌어지고 있습니다:
1. **DeepSeek의 서빙 스택이 정말 독보적으로 뛰어난가?** — vLLM의 비교 벤치마크로 어느 정도 근거 있는 논의가 가능해졌습니다.
2. **이 공개 수치가 추론 서비스의 높은 수익성을 증명하는가?** — 이는 워크로드 구성, 캐시 비율 계산 방식, 하드웨어 비용 포함 범위 등에 따라 결론이 달라질 수 있습니다.
